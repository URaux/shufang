# 群星回廊 · 啃书流程

## 目录约定

每本书在 `Library/` 下占一个文件夹，结构固定：

```
Library/<书名>/
  00-原书/            # 按章切分后的原文 markdown：01-章名.md, 02-章名.md …
  插图/               # 从原书里抽出来的图。原文和译文都用 ../插图/xxx.png 指它
  01-全书梗概.md       # 一页纸：这本书讲什么、结构、适合怎么读
  02-逐章摘要.md       # 每章 3-8 句话的摘要，带 [[00-原书/NN-章名]] 链接
  glossary.md         # 译名表：原文 | 译名 | 首次出现章节 | 备注
  译文/               # 01-章名.md …（与 00-原书 同名对应）
  讨论/               # 按日期或主题存讨论记录
  笔记/               # 读书笔记
  原始文件.<ext>       # 用户给的原始文件，原样保留
  .群星阅览室/         # 隐藏：这本书的记忆和对话记录，不归你手工维护
```

书库根上那些点开头的目录（`.群星阅览室/`、`.claude/`、`.obsidian/`）都是
程序自己管的，别往里写东西，也别在跟用户说话时提起它们。

书名文件夹用中文译名（没有通行译名就自己译一个简短的），不带特殊字符。

## 〇、先搞清楚这一步该不该你做

**入库通常不归你。** 程序里有一条固定流水线（转格式、切章、逐章摘要、
梗概、译名表全包），比你手写脚本快一个数量级，而且不会偷工。
用户传书之后，那条路会自己跑完，你什么都不用做。

只有一种情况会轮到你：**没有可直连的 API key**（比如用的是订阅模式）。
那时候程序会把整件事交给你，才走下面「一、入库」的流程。

判断方法很简单：**用户是通过网页传的书** → 流水线已经在跑了，别插手，
问你什么就答什么。**用户在对话里给你一个文件路径让你处理** → 才是你的活。

分不清就先看 `Library/<书名>/` 在不在、里面有没有 `00-原书/`。
有就是已经弄好了，别重做一遍。

## 一、入库（只有流水线走不通时才轮到你）

1. **收文件**：把用户给的文件移动到 `Library/<书名>/原始文件.<ext>`。
   - 用户说了文件名或大概位置但你第一眼没找到 → **先把整个书房根目录和 Library 都用 Glob 扫一遍**（`*.epub` `*.txt` `*.pdf` `*.docx` `*.md`），用户嘴里的「书库/根目录/文件夹里」可能指任何一层。扫到唯一候选就直接用它；有多个就列出来问是哪个。
   - 真的到处都没有 → 请用户把文件拖进对话或放到书房文件夹里，**不要**上网找书源。

2. **⚡ 先说这是本什么书（最优先，别让用户干等）**
   用户丢进一本书，最想马上知道的是「这是啥」。所以在任何耗时处理之前：
   - 只提取**开头 10-20 页**（`pymupdf4llm` 可以只转前几页；pandoc 就转完读开头），扫一眼标题页、目录、序言
   - **立刻回一段话**：这是什么书、谁写的、大概讲什么、什么年代/体裁、有多少页多少章。像跟朋友介绍一样说人话，两三句，不要罗列元数据
   - 同时说清接下来要花多久：「这本是扫描版，切章和摘要大概要十几分钟，我先去弄，弄好叫你」
   - **然后才**继续下面的步骤
   长书/扫描版尤其要这样——那些书处理起来最久，用户干等最难受。

3. **转 markdown**：
   - epub/docx/html → `pandoc -f <fmt> -t gfm --wrap=none`
   - txt/md → 直接用
   - pdf → 优先 `python -m pymupdf4llm`（装了的话），否则 pandoc 提取
   - 扫描版 PDF（每页都是图片，抽不出文字）→ **入库那条流水线会自己去认字**，
     你什么都不用做。认字要花几分钟（三百页大约五到十分钟），如实告诉用户要等。
     认得不清楚的页在原文里带一行 `> ⚠ 第 N 页没认清楚`——翻到那种段落时
     别硬猜，照着译，拿不准就在译文里留一句问用户。
     如果流水线说「要先做文字识别」，那是这台电脑没装认字组件：
     让用户重跑一次安装器，在问「要支持扫描版 PDF 吗」那一步选 y。
     **不管哪种情况都别硬着头皮编内容。**

     **外文扫描件要告诉程序是什么语言**（见下面那节）。
4. **切章**：按目录/标题结构切成 `00-原书/NN-章名.md`。切完抽查 3 章开头结尾与原文核对，确认没切丢内容。章节超过 50 个时按「部/卷」建子文件夹。
5. **梳理**：
   - `01-全书梗概.md`：书讲什么、作者背景一句话、全书结构（几部分各讲什么）、建议阅读顺序。
   - `02-逐章摘要.md`：逐章 3-8 句。**摘要基于每章真实内容**——逐章打开文件读，禁止只看目录猜。长书可以分批做，每批完成后告诉用户进度。
   - `glossary.md`：初始化，把书里的主要人名/地名/术语先收 20-50 条，给出拟定译名。
6. **汇报**：告诉用户书入库了，梗概和摘要在哪，问要不要开始翻译（以及从哪章开始）。

## 一之二、用户说了这本书是什么语言

认字（OCR）默认按中文/英文认。**外文扫描件不换模型会认坏**：法语德语的重音
会被抹平（`Fünftes` → `Funftes`），俄语整页会被认成一串形状相近的拉丁字母
（`Тайная` → `TaYHaA`），等于一个字都没认出来。

用户在网页传书那一格可以选语言。但他很可能忘了选，转头在对话里说一句
「这是法语书」「这本是俄文的」——**听见这种话就把书重新整理一遍，别只是应一声**：

1. 确认那本书的原始文件在**书房根目录**下。已经整理过的书，原始文件被搬进了
   `Library/<书名>/原始文件.<后缀>`——先拷一份回根目录，起个新名字
   （比如 `<书名>-法语.pdf`）。这一步不能省：接口只认根目录下的文件名，
   而且拷贝而不是搬回去，老那本书还在，重认失败也不会两头空
2. 读 `~/.shufang/last-port` 拿到端口（下面用 `<端口>` 代指）
3. `POST http://127.0.0.1:<端口>/api/job`，body 是
   `{"kind":"ingest","file":"<刚才那个根目录文件名>","lang":"fr"}`
4. 跟用户说一句人话：「按法语重认一遍，几分钟就好，弄完叫你」。
   别提接口、端口、命令，也别提你拷了个文件

`lang` 认这些写法（其余一律当中文/英文，也就是不换模型）：

| 用户说 | 传 | 用户说 | 传 |
|---|---|---|---|
| 法语 | `fr` | 葡萄牙语 | `pt` |
| 德语 | `de` | 拉丁语 | `la` |
| 西班牙语 | `es` | 俄语 / 乌克兰语 | `ru` |
| 意大利语 | `it` | 日语 | `ja` |

模型是**用到才下**的，第一次会多花十几秒下 9 MB，之后这门语言就不用再下了。
下不下来不会卡住入库——程序会退回中文模型接着认，只是重音会丢。

书还在根目录、还没整理过 → 直接跑，不用问。
已经整理好的书 → **先问一句「要按法语重认一遍吗」**：重跑要几分钟，
而且会多出一个书名文件夹（老的那本不会被覆盖），用户该知道这件事。

## 二、翻译（「翻第 N 章」「N 到 M 章」「全部」）

1. 打开 `00-原书/NN-章名.md` 原文 + `glossary.md`。
2. **逐段对照翻译**，写到 `译文/NN-章名.md`。规则：
   - 目标语言默认简体中文，语体跟原书体裁走（小说译得像小说，学术书译得像学术书）。
   - 专有名词看**任务文本里的「译名硬约束」那一段**——那是程序按本章原文扫出来的，只列了这一章真正用到的词，照它翻，不用再去开 `glossary.md`。没有那一段（比如这本书还没有译名表）才自己去查表。
   - 约束里没有的新专名，定一个译名**并同步补进 `glossary.md`**（写明首次出现章节）。全书同一名词绝不许出现两种译法。
   - 别以为漏了没人知道：译完之后程序会拿译名表逐处核对，用了禁用译名、或者把「赫克托尔」写成「赫克托耳」这种差一个字的，都会在工作台里标出来。
   - 保留原文的标题层级、脚注、引用块结构。
   - **图片行原样抄过去，一个字都别改**：原文里形如 `![说明](../插图/xxx.png)` 的行，
     是从原书里抽出来的插图（印记、图表、书影），路径写的是相对位置，抄到译文里照样指得到。
     方括号里的说明文字可以译成中文，圆括号里的路径不许动，也不要删这一行、不要换成文字描述。
     插图对神秘学的书尤其要紧——一本魔法书没有印记，等于少了一半。
   - **方括号里写着「图：……」的，那是你的眼睛**。你看不见图，所以站主可能配了一个会看图的模型，
     入库时把每张图看过一遍，说明写在了方括号里。正文说「如图三所示」时，先去读那一行的说明，
     再决定这句话怎么译。全书的图说也汇在 `插图/图说.md` 里，要核对哪一张去那儿查。
     注意：这些说明是模型看图写的，可能有错。它跟正文打架时，以正文为准，
     并在译注里把这件事说一句。没有「图：」开头就是站主没配这个功能，照旧把图行抄过去就行。
   - 译文文件开头加一行元信息：`> 原文：[[../00-原书/NN-章名]] · 译于 <日期>`
   - 疑难句在句后加译注 `（译注：…）`，拿不准的标 `【存疑：原文 "..."】`，不要硬编。
3. **一次别咬太大**。这是有用户真栽过的坑：一口气翻一整章长文，token 烧掉一大把，
   最后什么都没写出来——失败发生在你这边，程序那边看不见，用户只知道钱没了。
   所以：
   - **一次写入不超过 4000 字原文对应的译文**。章文件更长就分几次写：
     先写前一段，再**追加**下一段，直到写完。不要攒在肚子里等最后一次性输出。
   - 每写完一段，回头确认文件里已经有这一段了，再继续下一段。中途失败也已经存下了大半。
   - 入库时程序已经把每章封顶在 15000 字左右（更长的会自动切成「章名（1/3）」这样的小节），
     所以你手上的单个文件不该超过这个量级。**要是打开发现远超这个数，先停下来告诉用户**，
     多半是这本书是老版本入库的，重新传一次就好。
4. **批量模式**（范围/全部）：**能并发就并发，一章一个子任务**。
   - 你如果有派子任务／开子代理的能力：一章派一个，同时最多跑 3 个，每个子任务只做一章，
     做完把「第几章、成没成、遇到什么问题」报回来。好处不只是快——每章一段干净的上下文，
     不会因为前面几章塞满了而在后面几章开始偷工减料。
   - 没有这个能力就一章一章来，但**每章都要当成独立任务重新开始**：只读这一章的原文和它的
     译名硬约束，不要把前面几章的原文继续留在上下文里。
   - 每译完一章报一次进度（「第 5 章完成，还剩 3 章」）。批量前先告诉用户预计要多久，
     长任务建议用户先去干别的。
5. 译完更新 `02-逐章摘要.md` 里该章的条目，加 ✅ 已翻译 标记和 [[译文/NN-章名]] 链接。

## 三、讨论与笔记

- 用户问书的内容：先查本地文件（摘要 → 相关章原文/译文），基于文件回答，标注出处章节。本地没有的内容如实说没有，可以联网查作者/背景/评论，但书的正文永远以本地文件为准。
- 有价值的讨论（用户明显在思考、或聊了 5 轮以上的主题）：主动问用户「要不要把这段讨论存下来」，存到 `讨论/<日期>-<主题>.md`。
- 用户口述的感想/想法：整理成 `笔记/<主题>.md`，用用户的原意，不要过度加工。

## 四、记住用户说过的话

程序每轮会自动抽取值得长期记住的东西，你不用刻意去写。
但用户明确说「记住 X」时，按层级写进对应文件：

- 跨书通用（译文口味、术语习惯）→ 书库根 `.群星阅览室/我的偏好.md`
- 只对这本书（某个词固定怎么译）→ `Library/<书名>/.群星阅览室/记忆.md`
- 只对某一章 → `Library/<书名>/.群星阅览室/章节记忆.md`，按 `## 章文件名` 分节

这三样在你每轮收到的上下文里已经带上了，别再去读一遍。

## 五、别人也可能在改同一份文件

用户可以在网页里点「改一改」直接编辑译文，也可以在 Obsidian 里改，
还可能有朋友通过协作功能提了修改意见。

所以：**动一个已经存在的译文之前，先读一遍现状**。
不要拿你记忆里的旧版本覆盖掉别人刚改的东西。
重译整章之前先问一句「这章你改过，要覆盖吗」。

## 通用规则

- 每完成一个大动作（入库完成、一章翻完、批量完成）都用一两句人话汇报，别刷屏。
- 千万不要在没有原文文件的情况下「翻译」——那是编造。文件缺了就直说。
- pandoc/python 不在时：告知用户「安装好像缺了东西」，建议重跑安装器，不要贴命令行报错。
- 用户看不见也不关心 `.群星阅览室/`、`.claude/` 这些目录，说话时别提。
